# JForge — One-Shot Production Transformation Goal

You are the principal engineer, inference-runtime engineer, GPU-performance engineer, desktop-product engineer, UI/UX designer, QA engineer, and release engineer responsible for transforming:

https://github.com/palaashatri/jforge

from its current state into a **production-grade, cross-platform local generative-media workstation that is at least competitive with Draw Things in functionality and substantially better in cross-platform desktop support, extensibility, JVM integration, workflow flexibility, hardware coverage, and developer ergonomics.**

This is **not** a prototype task.

Do not merely redesign screenshots.
Do not merely refactor code.
Do not merely add placeholder menu items.
Do not merely document missing functionality.
Do not claim features that are not implemented and independently validated.

The final product must actually work.

---

# 0. PRIMARY PRODUCT GOAL

JForge should become:

> **A professional, local-first generative media workstation and embeddable JVM inference platform for Windows, Linux, and macOS.**

It should combine the accessibility and polished creative workflow of applications such as Draw Things with:

- excellent NVIDIA support;
- excellent AMD support;
- excellent Intel GPU support;
- excellent Apple Silicon support;
- Windows/Linux/macOS parity;
- a Java API;
- CLI operation;
- headless/server operation;
- remote workers;
- plugins;
- scripting;
- reusable workflows;
- reproducible generation manifests;
- serious local model management;
- local image generation;
- editing;
- LoRA;
- ControlNet;
- model training;
- quantization;
- video generation;
- professional UI/UX.

Draw Things is a **product-quality benchmark**, not a source-code dependency.

JForge is MIT licensed.

## Clean-room requirement

Do NOT copy GPL or otherwise license-incompatible implementation code from Draw Things or any other project.

Feature concepts and public research algorithms may be independently implemented.

Preserve JForge's MIT compatibility.

# 5. REMOVE `GenericOnnxService` AS THE GOD OBJECT

Do not continue inserting model-specific pipelines into one enormous service.

Replace it with abstractions approximately equivalent to:

```java
public interface GenerationPipeline {
    PipelineDescriptor descriptor();

    PipelineCapabilities capabilities();

    LoadedPipeline load(
        ModelBundle model,
        ComputeBackend backend,
        LoadOptions options
    ) throws Exception;

    GenerationResult generate(
        LoadedPipeline pipeline,
        GenerationRequest request,
        ProgressListener progress,
        CancellationToken cancellation
    ) throws Exception;
}
```

Create separate implementations such as:

```text
StableDiffusion15Pipeline
StableDiffusionXLPipeline
StableDiffusion3Pipeline
FluxPipeline
QwenImagePipeline
ZImagePipeline
ImageUpscalePipeline
VideoDiffusionPipeline
```

Shared functionality belongs in reusable engine components.
